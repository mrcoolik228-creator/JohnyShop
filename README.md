# JohnyShop
# 🎌 Аниме-магазин «JohnyShop» — Проектирование базы данных

Информационная система для автоматизации учета товаров, управления клиентской базой и обработки заказов в специализированном интернет-магазине аниме-мерча и манги **«JohnyShop»**.

---

## 📋 Описание предметной области

Система предназначена для хранения актуального ассортимента магазина, регистрации покупателей и учета продаж. В базе данных фиксируются подробные характеристики каждого товара (наименование, тип мерча, принадлежность к аниме-тайтлу, цена и складской остаток), контактные данные клиентов, а также история заказов с детализацией купленных позиций.

Накопленные данные позволяют администрации магазина:
* Отслеживать популярность конкретных аниме-франшиз.
* Контролировать остатки товаров и вовремя пополнять склад.
* Отслеживать статусы доставки заказов.
* Рассчитывать общую выручку магазина за любой период.

```mermaid
    }
```

## 🔗 Логика связей и нормализация

* **Клиент — Заказ (`1:N`):** один покупатель может оформить множество заказов, но каждый конкретный заказ принадлежит строго одному клиенту.
* **Заказ — ПозицияЗаказа (`1:N`):** один заказ может включать в себя множество разных позиций мерча, но каждая строка чека относится только к одному заказу.
* **Товар — ПозицияЗаказа (`1:N`):** один и тот же товар может встречаться в разных заказах покупателей, но в конкретной позиции заказа указан строго один товар.

> **Разрешение связи «Многие-ко-многим» (`M:N`):** логическая связь между сущностями `Заказ` и `Товар` (в одном заказе много товаров, и один товар покупают в разных заказах) успешно разрешена с помощью ассоциативной сущности **`ПозицияЗаказа`**, которая разбила её на две связи типа `1:N`.
